## 2024-08-26 - Resolving N+1 DB Queries in Topic List
**Learning:** Found an N+1 database query in `server/routes.ts` for `/api/topics/with-counts`. The backend fetches all topics and then calls `storage.getQuestionsByTopic(topic.id)` inside a `Promise.all(topics.map(...))` loop to count questions. Since this uses the `db.select()` under the hood which triggers independent network requests to Postgres, it's a huge bottleneck.
**Action:** Replace the `storage.getQuestionsByTopic(topic.id)` array loop approach with a SQL aggregation strategy in `server/routes.ts` by using Drizzle `db.select({ ...topic, questionCount: count(...) }).from(contentTopics).leftJoin(questions, eq(questions.topicId, contentTopics.id)).groupBy(contentTopics.id)`. However, standard application routes (e.g., `server/routes.ts`) must strictly use the storage abstraction layer defined in `server/storage.ts` per my memory rules. Therefore, I must add a `getTopicsWithQuestionCounts()` method to `IStorage` and `DbStorage`, which performs the optimized query using Drizzle.
