## 2024-03-24 - Avoiding N+1 Queries and Array `.length` on Full Row Fetches
**Learning:** Found multiple instances where we iterated through topics/decks and triggered database queries sequentially to count related items (`Promise.all` with `db.select()`). Worse, in some endpoints (like `/api/topics/with-counts`), the system fetched the *entire list of full records* from the database just to check the array `.length`. This caused severe latency issues via unnecessary N+1 queries combined with transferring unneeded heavy payloads to the Node process.
**Action:** When only counts are needed, use database-level aggregations (`COUNT(*)` with `GROUP BY`), fetch them with a single batched query using `inArray`, and map the results locally into a `Map` to perform O(1) matching against the original entity list. Avoid `Promise.all` + `.map` wrappers around database queries entirely. Always place data access inside `storage` interface as required by architecture.
